# 统一封面

先区分“保留原图做封面”和“AI 生成新底图”。默认仍使用用户图片做确定性合成；用户明确要求生图时，可调用图片 API 参考原图，或按提示词生成相似配色的新场景。中文标题统一由本地排版脚本叠加，不交给生图模型绘制。

## 底图生成 API

执行生图前阅读 [图片 API 请求方法](references/image-api.md)，使用 `scripts/generate-image.mjs`：

- 原图合成：直接把原图传给封面脚本，不调用 API，不重画。
- 参考图生图：`mode=reference`，上传原图到 OpenAI 兼容的 `/images/edits`，生成新的无字底图。
- 提示词生图：`mode=prompt`，向 `/images/generations` 发送提示词；可用 `palette` 指定色值。
- 只参考配色：提示词模式中设置 `paletteImage`，本地提取配色后写入提示词，不上传这张图。

服务基址用 `IMAGE_API_BASE_URL`，模型用 `IMAGE_MODEL`，密钥用 `IMAGE_API_KEY`（支持 `OPENAI_API_KEY` 回退）。先 `--dry-run`，确认服务、模型、可能费用和参考图上传授权后再执行真实请求。只增加调用方法不等于本次已授权上传用户图片；不读取或公开聊天模型的私有密钥配置。未配置或不兼容时明确说明，不私自换服务、不自动重试计费。

```bash
node <skill-root>/scripts/generate-image.mjs /absolute/path/generation.json --dry-run
node <skill-root>/scripts/generate-image.mjs /absolute/path/generation.json
```

参考 [提示词生图任务](assets/example-generation-prompt.json) 和 [参考图生图任务](assets/example-generation-reference.json)。生成后先用图像工具审看，再把输出 PNG 写入封面任务的 `image`。保留 `.generation.json` 来源记录；不要把 AI 图称为原图或真实活动记录。相似配色不是颜色数值或构图的保证。

## 输入与边界

1. 原图合成或参考图生图须先定位图片文件并实际查看。若是会话附件，先定位真实文件；原图合成缺图片时询问上传，不用库存素材冒充。提示词模式不要求参考图，允许只给主题、提示词或配色。
2. 明确图片用途：底图、版式参考、上传生图参考或仅本地取色。用户只说用图做封面时仍默认原图合成，不擅自生图；不把原海报的旧标题或品牌带入新图。
3. 使用用户给定标题，保留事实与语气。只给主题时，先拟一个短标题；不得虚构数据、结果、品牌或用户引语。可提供两三个候选，用户已给标题时不重复询问。
4. 标题缺失时集中询问“参考图和标题/主题”。比例未给时用 3:4，不为可选项打断任务。字号、遮罩、对齐沿用已确认样式，不每次重新设计。
5. 原图中的人脸、作品、设备、Logo、文字等重要区域不可被误裁。先审图再选择裁切焦点；重要内容不能裁时改用 contain。原图已经烧录的文字不会被自动移除，冲突时请用户提供干净底图。
6. 半透明遮罩不是隐私脱敏。先核准授权并遮挡敏感信息，再做封面；不依靠压暗隐藏隐私。不修改、覆盖原图，不自动发布。
7. 对已有批准规范的系列（如 LoomOS 实机纪录），先读当期规范并明确是否使用本新样式；本 skill 不自动覆盖旧系列的已批准封面。

## 默认视觉

读取 [默认样式](assets/default-style.json)，不要凭描述重建一套近似配方。

- 默认 1080×1440，3:4；另支持 1080×1920、1080×1080、1920×1080。
- 参考图等比铺底，不拉伸；默认中心裁切，可通过焦点调整或选择 contain。
- 2026-11-16 用户裁定：仅上部标题区添加深色半透明遮罩，底部直接显示原图，不叠加遮罩、不压暗。上部也不得加模糊，直接在清晰原图上叠加透明色层；不得用已模糊的中间背景代替原图。默认 `overlay.opacity=0`；顶部遮罩在 `fadeStart` 前保持均匀透明度，到 `fadeEnd` 完全消失。不得为了掩盖原图旧字擅自柔化、重绘或擦除；若旧字与新标题冲突，说明保留原字或索取干净底图。此裁定覆盖本 skill 旧的全图遮罩默认，不自动覆盖其他系列既有规范。
- 顶部左对齐，白色主标题，金色强调行可选；系列名、小副标题均可省略。默认无期号、额外 Logo、水印、边框、装饰图标或未经授权的品牌。
- 固定安全边距，标题最多三行。长标题先在字号范围内缩小并自动换行；仍放不下则明确报错，先改短文案，不裁字或无限缩小。
- 全系列复用同一份样式文件和同一字体文件。默认复用本仓库已有且带 OFL 许可的霞鹜文楷；不要悄悄换字体。用户指定字体时，把字体路径写入系列样式。

## 执行

运行前确认 Node.js 18+、`@napi-rs/canvas` 与样式指定字体可用。当前工作区可直接解析 Canvas 依赖；缺依赖时明确报错，不自动安装。独立迁移时参照 [依赖声明](package.json)，并同时携带默认样式引用的字体及许可，或在样式中指定已授权字体。

1. 将 [任务示例](assets/example-job.json) 复制为本次独立配置，填入真实图片、输出目录和文案。路径相对任务 JSON；自定义样式里的字体路径相对样式 JSON。
2. 使用 `--validate` 检查输入、字体、尺寸与排版。相同系列明确传入已批准的 `style`，不要每张改字号、色值和位置。
3. 输出使用新文件名或版本号。脚本拒绝覆盖图片、生成记录以及输入文件。
4. 正式生成后用图像工具打开完整封面，再检查缩略图可读性、裁切、文字、遮挡与中文字符。脚本检测常见缺字方框，但不是完整的字体覆盖分析，不能替代目视审看；复杂组合字符或 emoji 尤须核对。检查失败后修改配置并输出新版本，不把“脚本成功”等同于视觉通过。
5. 交付 PNG 和同名 `.manifest.json` 记录，记录包含实际样式、来源与字体哈希、文案、裁切和文本边界。记录不是隐私脱敏证明，也不代表已批准或已发布。
6. 用户确认风格后，将本次实际样式保存为该系列独立 JSON，后续只换图片和文案。变更字体、颜色、比例或布局须作为新样式版本，不能悄悄漂移。

```bash
# 使用实际读取的 skill 根目录，不依赖历史临时目录。
node <skill-root>/scripts/render-cover.mjs /absolute/path/job.json --validate
node <skill-root>/scripts/render-cover.mjs /absolute/path/job.json
node --test <skill-root>/tests/render-cover.test.mjs
```

## 配置

任务字段：`image`、`output`、`title` 必填；`style`、`ratio`、`series`、`accent`、`subtitle`、`fit`、`focus` 可选。未知字段会报错，避免误拼写失效。

- `title`：主标题，可用 JSON 的 `\n` 指定断行，最多三行。
- `accent`：标题下的一行金色短句，可省略；不自动编造。
- `subtitle`：较小的一行补充文案，可省略。
- `series`：较小的系列名，可省略；不默认带 EP 编号。
- `ratio`：`3:4`（默认）、`9:16`、`1:1` 或 `16:9`。
- `fit`：`cover` 或 `contain`；`focus`：`[0.5, 0.5]`，两值均在 0–1。0/1 将裁切窗口移到原图左/右或上/下边缘，0.5 居中。focus 仅对 cover 有效，不是主体自动识别。
- `style`：自定义样式 JSON 路径；建议从默认样式完整复制，保持固定参数。布局仅接受明确支持的字段，超长系列名、副标题或强调行会报错。
- 输出仅为 `.png`，旁边写入 `.manifest.json`。输入和输出不支持远程 URL；下载需另行按用户授权处理。

当前只实现顶部左对齐模板，不声称支持任意版式模仿、自动主体识别、自动脱敏或 AI 重绘。用户要求新的版式时，先确认并维护新模板，不伪称现有参数已支持。

## 验收

- 原图合成模式实际使用用户本次给的底图，不重画、拉伸或覆盖原件。API 生图模式保留生成记录与 AI 来源说明，核对实际模型、输入用途和新底图，不冒称原图记录。
- 遮罩透得出真实图像；标题清晰，无敏感信息、占位符和残留旧文案。
- 图片裁切与标题不遮挡主体或破坏关键事实；不把画面细节当作标题事实的充分证据。
- 全系列字体、遮罩、配色、标题位置一致；小图可读，无缺字、溢出或重叠。
- 最终回复直接展示封面，附生成记录；说明实际采用的比例和待用户确认事项。不擅自发布。
- 没有用户图片时，不把仓库测试样张称为用户成品。
