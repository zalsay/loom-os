# MiMo配音

使用前检查官方当前文档：<https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5> 。以下配置已用于织界V12，记录于2026-10-10，未来接口变化时更新。

- POST `https://api.xiaomimimo.com/v1/chat/completions`，Bearer认证与JSON请求。
- 模型 `mimo-v2.5-tts`，中文预置音色 `茉莉`，非流式 `wav`。
- 风格指令放 `role: user`，逐字稿放 `role: assistant`；解码 `choices[0].message.audio.data` 的Base64。
- 温暖、清晰、略轻快的普通话女声，像引导孩子探索的年轻导师；AI读作A I，织界读作zhī jiè。每段按窗口自然读完，保持音色一致。
- `scripts/mimo_tts.py` 按文本、模型、音色、风格、时长窗口与接口生成指纹；完全匹配才复用音频。

只从当前进程环境 `MIMO_API_KEY` 取密钥。不硬编码、不写进skill、项目、版本库、日志、ZIP或示例，不复述旧对话密钥。缺少配置时完成其他环节并如实说明配音状态。

制作配音仅提交需要朗读的逐字稿，不附原始课堂文档或额外隐私字段。TTS授权不涵盖云端ASR、克隆、其他语音服务或发布。默认本地时长/峰值检查与人工试听；云端转写由用户明确要求或授权后再做。自动审批拒绝时不要改接口、编码或执行路径绕过。

翻页后约0.6秒开始朗读，片尾留短暂余韵。测实际时长，超出窗口优先精简文案或调镜头，保持音高的变速最多1.2倍，不能截句尾。SRT按句长度分配时间只是近似；实际听检负责口误与语感，不能把数值检查称为听过。

## 音色复刻（voiceclone，仅限用户明确要求）

用户提供本人录音并明确要求复刻时用模型 `mimo-v2.5-tts-voiceclone`：样本转 mp3 后以 `audio.voice = data:audio/mpeg;base64,...` 传入（<10MB），指令在 user message、文本在 assistant content。克隆语速完全跟指令走：「自然温和/从容」≈1.5-3字/秒拖沓，须明写「正常偏快、像跟朋友聊天、X秒读完」。

**语速定标（EP01 三轮实测收敛，用户定稿 ~5字/秒档）**：实拍过程片旁白目标 **4.4-5 字/秒**（186 字 → 42.4s ≈ 4.4 字/秒获用户通过；3.6 字/秒被评「太慢」，6.6 字/秒被评「太快」）。达成该档的指令写法：「用正常语速朗读，像跟朋友面对面聊天，吐字干净利落，不要拖沓、不要停顿过长，整篇在约 N 秒内自然读完，语速适中偏快一点，但吐字要清楚。」其中 N = 字数 ÷ 4.4。

**语速控制只能实测收敛（硬规则）**：目标秒数与产出**非线性**——EP01 案例：目标 46s 出 51.7s、目标 37s 出 42.4s、目标 34s 反而出 51s。每换一档指令必须：①合成后 ffprobe 实测时长；②同指令重摇一次确认档位稳定（波动 >±10% 说明该档不稳，换措辞再试）；③取稳定档交付，不要为凑秒数反复摇。文案加长语速会自动加快（158 字→44.5s vs 186 字→28.2s 同指令），按「字数÷4.4」反推目标秒数。**多摇时每次合成立即存档（文件名含实测时长）**，命中目标档前不要覆盖——EP04 案例：连摇 10 次落点 33-56s（146 字同指令），仅两次接近 4.4 档，37.44s 的好 take 因未存档被下一摇覆盖，被迫用 39.36s + atempo 1.1861 补救。

**整篇合成再切片（硬规则）**：逐段调用会产生段间音色/语速漂移（EP01 用户实测反馈）。多段配音必须全文一次合成，再按分镜切片：silencedetect 句间停顿与字数推算句边界交叉定位切点，取句后长停顿中点，`-c copy` 无损切片；切片须全部落入分镜窗口。静音阈值按样本底噪调：干净样本 -33dB/0.16s 起步；底噪高的样本先带通滤波（`highpass=f=200,lowpass=f=3800`）再用 -27dB/0.10s。详细配方见 [竖版小红书版规范](references/xhs-vertical.md)。克隆语音句内有自然停顿，时长验证用连续包络，勿单点 RMS 采样。


## 旁白文风（v007/v008 定稿，用户硬要求）

- **叙述者 = AI（织界），第一人称「我」**：旁白里不出现第三人称「AI」；视角为「我负责干活，人负责把关」。屏幕标题、封面、发布文案（标题+简介+看点+置顶评论全文）同步过同一检查（如「AI 接手第一次体检」被否 →「我没急着动手 / 先摸个底」；EP03 简介初稿「给 Mosaico 做体检的不是我，是 AI」把「我」让给人类，同样被否）。
- **去 AI 腔（humanizer 原则）**：禁排比式罗列（「串口在不在，端口有没有…」）、大纲式转场（「接下来验证…」）、口号式三连；要加真实心态（「说实话我心里也没底」「谁都不敢打包票」）、第一人称动作（「我就一条条试」「我没急着动手」）、长短句交错。
- 事实边界不放松：只陈述画面可见内容，不猜不装懂的话术反而是人味来源（「跑不通就记下来，不猜也不装」）。
- **电报体也是 AI/程序员腔（EP06 v001 用户反馈）**：短促词组罗列（「检查按钮按下去，跑了，然后停了」「卡住的不是检查，是交卷」）读起来像终端日志，不像人说话。要成句、带口语连接词与语气（「检查按钮按下去，它真的开跑了——跑了一阵，自己停了下来」）；加「说实话」「其实」「你猜怎么着」这类真实语气，但一集最多两处，别变口头禅。

## 旁白字数必须先按片长反推（EP06 v001 硬教训）

- **顺序是「先定片长 → 反推字数 → 再写旁白」，不能先写旁白再套片长**：EP06 v001 旁白 101 字→23.5s，片长 33s，最后 10 秒只有画面没声音，用户直接判不通过。
- 公式：`目标字数 ≈ (片长 − 起播偏移 0.5s − 尾部留白 1.5s) × 4.0~4.4 字/秒`。33s 片 → 约 125–135 字。
- 写完后先数汉字（`len([c for c in TEXT if "\u4e00"<=c<="\u9fff"])`），与目标差 >10% 就改文案，不要靠 atempo 硬拉（拉快会丢人味，拉慢会拖沓）。
- **三幕切点由旁白的幕边界反推**，不是先剪画面再塞旁白：拿 whisper 各段起止 ÷ atempo + 0.5s 得到「幕1 结束/幕2 结束」的真实秒数，据此设 xfade offset（片长不变，只调 S1/S2/S3）。

## 字幕轴程序化生成（禁止手写时间）

- 手写 CAPS 时间轴是最容易错位的一环。固定做法：whisper 段 → 每段按分句字数等比切分 → 输出 `clone/caps.json`（含 start/end/text）→ 渲染脚本 `json.load` 直接吃，不写死秒数。
- 分句表必须与 whisper 段 1:1 对齐（`assert len(segs)==len(CLAUSES)`），对不上说明 TTS 漏句或断句不同，先修文案再重摇。

## 语速与完整性校验（v007 流水线，强制）

- 语速不靠指令赌（同指令落点 24.8~44.3s 六档不稳）：整篇合成后用 **atempo 后处理精确校准到 4.4 字/秒**（N = 字数 ÷ 4.4），降速方向质量无损；指令只决定大致档位。
- **整篇合成必须做完整性验证**（模型会漏句/跳句）：本地 Whisper（base, zh）转写全文与台本逐句比对；whisper 分段时间戳直接用于字幕对齐（变速后 ×(1/atempo)+摆放偏移）。
- whisper 安装绕过沙箱：pip 装 torch/tiktoken/numba 等 wheel 依赖，whisper sdist 手动解包进 site-packages。
