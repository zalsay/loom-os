# 织界 Team 讨论与评审

## 入口和授权

- 开始前读取项目根目录 `copis/宣传计划/00-策略与复盘/AI团队协作手册.md`、`copis/宣传计划/00-策略与复盘/运营工作流手册.md` 的 WF-2，以及当期记录、已有裁定和相关证据。以用户最新明确指令、实际授权和当前环境能力优先；不把历史建议、全票或多数票当作执行授权，不重开已确认且未被用户改动的决策。
- 团队分工：主持人负责材料、交叉核对和汇总；按议题分配内容策略、运营策略和数据审计等独立视角。使用宿主实际提供且可核验的独立评审工具，当前优先 `run_cli_agent`；角色、模型和运行结果以实际配置与回执为准，不把普通子代理冒充 Claude、agy 或 Codex。用户点名的成员不可用时明确标缺席，并说明实际参与者。
- 仅讨论不等于授权发布、改稿、改配置或新建定时任务。标题、叙事、镜头、文案等制作决定须先讨论、汇总分歧并交用户确认；已授权方案内按用户要求执行。

## 准备统一简报

1. 明确本次议题、范围、预期产出及哪些事项只讨论不执行。先检查是否已有同议题进行中的任务或讨论记录；用户要求继续时优先查原任务，不重复发起。需要采集数据时遵循项目 `daily-platform-data` Skill 和手册 WF-1；若数据未采齐而用户仍要求分析，明确标“部分完成”、缺口与条件，不能冒充完整分析。
2. 阅读适用的用户最新裁定与已锁约束，写入同一份**自包含简报**：背景、目的、已定约束、证据路径、来源、采集时刻、平台统计窗口、作品身份、数据层级、可信度和缺口；OCR 未核验的数字明确标候选。区分昨日、实时、累计、所选窗口及单篇/账号口径；不跨平台混算，不用观看÷曝光替代官方 CTR。
3. 列编号问题：事实与口径、可支持的有限结论、缺失证据与优先级、选项与风险、需用户拍板事项。要求首轮独立作答、明确事实/推测/建议、引用依据、指出反例；无数据不猜测算法机制或因果。
4. 临时简报放当前会话 scratch 目录；不复制密钥或不必要的个人信息。简报需能让评审者不依赖历史对话独立完成。

## 邀请、首轮与跟踪

- 用户要求 Claude、agy、Codex 时，优先调用宿主的 `run_cli_agent`，分别设置 `provider: "claude"`、`"agy"`、`"codex"`。不要用 Runner，也不把普通 `subagent`、`Task` 或默认角色冒充这些指定成员。工具缺失、启动失败、退出码非 0 或没有有效输出时如实标缺席或失败；仅在用户同意替代且宿主允许时使用其他评审方。
- 向每个 provider 的 `prompt` 发送**同一份完整简报**，再追加该成员的独立评审侧重、禁止修改文件、禁止再委派和报告格式。首轮不得引用其他成员输出。`cwd` 使用项目根目录，`read_only: true`，`timeout_seconds` 按议题设置；`read_only` 调用可并行，宿主串行执行时逐一调用并保留独立性。
- 记录每次调用的 `provider`、请求 `model`、回执中的 `cliModel`、`reasoningEffort`、`readOnly`、`exitCode`、`durationMs`、输出截断/溢出路径及结论。只有 `exitCode: 0` 且拿到实际评审内容才算完成；`timedOut: true`、非零退出、空输出或仅有 stderr 均不得冒充已完成。
- `run_cli_agent` 是同步工具，不返回可恢复任务 ID，也没有 `TaskWait`。超时或失败后先核对已有回执和缺口，再决定是否人工重试；不要重复启动已成功或无新增信息的调用。

### run_cli_agent 调用约定

- **统一输入**：每次只传 `provider`、`prompt`、可选 `model`、`cwd`、`timeout_seconds` 和 `read_only`。该工具没有 `task`、`tasks`、`chain`、`sandbox`、`printTimeout`、`autoApprove` 或独立 `effort` 字段，不要沿用旧 subagent 参数。
- **默认模型**：省略 `model` 时使用当前插件配置：Codex `gpt-6.1-sol--high`，agy `gemini-3.8-flash--high`，Claude `haiku-5-5--high`。`--high` 是统一推理档位写法，由工具按各 CLI 原生参数转换；回执同时给出请求 `model` 和实际 CLI 参数 `cliModel`。
- **只读评审**：始终设置 `read_only: true`。Codex 使用 read-only sandbox；Claude 限制为 `Read,Glob,Grep` 并拒绝交互式授权；agy 使用 sandbox + plan mode。不要仅靠 prompt 声称只读。
- **输出判定**：`stdout` 是评审正文，`stderr` 只作诊断；同时检查 `exitCode`、`timedOut`、`stdoutTruncated`、`stderrTruncated` 和 spill path。成功回执后仍要交叉核对证据，不能把模型自述或退出码 0 当成事实正确。
- **模型覆盖与回退**：用户点名其他模型时，以 `model: "模型--effort"` 传入；不需要覆盖时省略，让默认值生效。只有回执明确表明模型不可用且尚未产生有效评审时，才可按用户或当期规则人工重试一个备选模型，并同时记录两次请求与实际 CLI 参数。超时、取消、429/503、网络错误或已有部分输出不得盲目换模型重跑。

## 汇总、记录与验收

- 收到首轮答复后逐一核对原材料和数字，分别列出各成员实际观点、共识、分歧及其理由、事实/推测/建议、证据不足与待补数据；不把个别意见包装为全员共识。缺席者、未回复者、模型回退、数据缺口和独立性限制均显式标注。数据能解决的分歧先补数据；真实、合规与隐私优先，不把平台机制猜测写成事实。
- 将当期简报、参评状态、原意见或可追溯引用、证据与口径、交叉核对、分歧、建议、用户决定和执行状态分别记录到 `copis/宣传计划/00-策略与复盘/EP讨论/` 适当文件；数据分析可使用“双平台数据团队讨论-YYYY-MM-DD.md”等现有命名。先读同名文件，保留历史，采用追加方式标明实际时间；临时结果与最终裁定分开。缺席、未完成和未确认写清楚，不能抹去历史观点或替用户填写决定。
- 验收：统一简报包含范围、约束、证据与编号问题；有各成员实际调用与回复状态；结论不超出证据；缺口有下一步和责任人；文件引用可访问；用户裁定与执行授权分离。若调用失败或评审未完成，标记“进行中/部分完成”，提供已完成/失败/缺席成员、回执状态和人工重试条件，不宣称团队分析完成。
