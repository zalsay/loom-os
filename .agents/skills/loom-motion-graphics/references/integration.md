# 历史二维动效接入参考

> 2026-11-09：默认入口已改为项目 `tools/loom-video-office/README.md`。本文件仅用于旧二维路线，不覆盖当前固定双窗口、统一办公场景及「含AI生成视频」标注。

动效段是**独立渲染的 1080×608 或 1080×800 片段**，再与实拍 overlay 合成，不直接写进主 filter_complex 的长表达式。这样改一个 beat 只需要重渲动效段，不重来整片。

## 一、放在哪个区

- **设备区**（y=280，1080×608）：相机画面全黑/无信息时优先放这里。相机黑屏在本系列是常态（夜间、未连接），把动效放这里既补空位又不伪造设备状态。
- **终端区**（y=888，1080×800）：终端文字太密或路径过多时，用动效替代表达，但**终端实拍是证据，能留就留**。稳妥做法是前半实拍、后半动效，让观众先看到原始画面再抽象。

判断顺序：先看相机有无有效信息 → 有则动效去终端区；无则动效去设备区，终端区保留实拍。

## 二、时序对齐

1. 先出旁白（整篇单次合成），停顿检测仅辅助定位；通过逐句听检或可靠对齐结果核准句界，不能按分句汉字数分配时长后宣称已同步（详见 `create-zhi-jie-video` 的剪辑规范）。
2. 取每个 beat 对应的句子起点作为 `start`，下一句起点作为 `end`；不要用「视频第几秒」硬编，因为重新配音后全部会偏。
3. 加 0.5 秒起播偏移后，字幕和动效都要跟着这个偏移走。

## 三、合成片段

```bash
# 1) 渲染动效段（1080x608）
python3 scripts/motion_kit.py spec.json 动效段.mp4

# 2) 合成：设备区放动效，终端区放实拍
ffmpeg -i 终端实拍.mp4 -i 动效段.mp4 -i 旁白.wav -i bgm.wav \
  -loop 1 -framerate 30 -i 底部装饰.png \
  -filter_complex "\
[0:v]trim=start=55:duration=22,setpts=PTS-STARTPTS,<隐私遮挡>,crop=1428:1058:12:0,scale=1080:800,fps=30,setsar=1[term];\
[1:v]fps=30,scale=1080:608,setsar=1[dev];\
color=c=0x1A2227:s=1080x1920:r=30:d=22[base];\
[base][dev]overlay=0:280[b1];[b1][term]overlay=0:888[b2];\
[b2][4:v]overlay=0:1688,ass='字幕.ass'[v];\
[2:a]adelay=500|500,volume=1.15[va];[3:a]atrim=0:22,volume=0.8,afade=t=out:st=20:d=2[ba];\
[va][ba]amix=inputs=2:normalize=0,loudnorm=I=-14:TP=-1.5:LRA=11,aresample=44100,alimiter=limit=0.80:level=disabled[a]" \
  -map '[v]' -map '[a]' -t 22 -c:v libx264 -pix_fmt yuv420p -c:a aac 成片.mp4
```

要点：
- 动效段与实拍段都要 `fps=30`、`setsar=1`，否则 overlay 会抖。
- 动效段时长必须等于 `-t` 值，短了会黑帧，长了会被截断。
- 遮挡（drawbox）在 `crop` 之前做，坐标用源尺寸；聚焦蒙层同理。

## 四、验收（每次都要做）

1. **抽帧看四个 beat**：起点、持稳、切换点各一帧，共 6–8 帧，确认没有半透明叠字、没有元素出框。
2. **数字复核**：动效里的每个数字都要能在验收记录里找到原值。1253 不能写成「一千二百多」或 1200。
3. **四态条复核**：未发生的状态必须仍为 dim 色并有文字说明。
4. **隐私**：动效里不得出现本机路径、用户名、内部 session id。
5. **听感**：动效起点与旁白句子起点对齐，允许 ±0.3 秒。
6. 全片解码通过、时长/分辨率/帧率/音轨参数一致。
