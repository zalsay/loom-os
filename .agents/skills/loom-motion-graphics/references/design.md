# 二维动效设计参考（历史路线）

> 2026-11-09：后续实机纪录默认使用项目 `tools/loom-video-office/README.md` 中的 Three.js 办公动画框架。下文只供明确要求二维信息图时参考；不再强制上下分区，也不禁止有叙事目的的三维镜头。早期研究对象 showlab/Code2Video 不等于用户参考视频中的 OpenSenseNova/SenseNova-6.8-Code2Video。

## 一、为什么用代码画，而不是剪辑关键帧

Code2Video（showlab/Code2Video，ICML 2026，MIT）的做法是用 LLM 产出可执行动画代码（Manim 场景），渲染失败就把 stderr 喂回模型改代码，最多 3 次；渲染成片后再用视觉模型抽帧评审布局，回炉改代码。它之所以好看，不是因为 Manim，而是三件事：

1. **矢量绘制**：数字、方块、连线都是几何图元，放大不糊、配色可复用。
2. **锚点约束**：强制用 6×6 网格定位，禁止 `move_to()` 这类手感定位，于是布局稳定、可批量套。
3. **逐段渲染 + 可重试**：一节一个场景，失败只重渲一节，不重来整片。

织界不需要搬 Manim（依赖重、渲染慢，且我们 90% 画面是实拍）。用 Pillow 逐帧 + ffmpeg 已经能覆盖所需动效，成本低一个量级，而且能读项目里的真实数字。

## 二、织界自己的栅格

竖屏 1080×1920 固定五区，动效只能落在空白区，不能遮证据：

| 区域 | 纵向范围 | 用途 |
| --- | --- | --- |
| 标题带 | 0–280 | 徽章、T1、T2 |
| 设备区 | 280–888 | 动效或相机实拍（1080×608） |
| 终端区 | 888–1688 | 终端实拍或动效（1080×800） |
| 字幕带 | 约 1540–1640 | 烧录字幕，动效内容要避开 |
| 装饰带 | 1688–1920 | 底部 Logo |

动效内部再用 6×6 栅格：所有元素以 `w/6`、`h/6` 为单位定位，不写死像素偏移。这条约束能防止「A 集改了字号，B 集就错位」。

## 三、配色与字体

只用五个色，全部来自品牌：

| 名称 | 值 | 用途 |
| --- | --- | --- |
| bg | `#141B1F` | 动效底，接近终端底色，切换时不出戏 |
| white | `#F8FFF8` | 主文字 |
| gold | `#FAC864` | 强调数字、已完成节点 |
| red | `#FF9678` | 失败、未发生、阻断 |
| dim | `#6E7E86` | 次要说明、未点亮节点 |

字体固定 Hiragino Sans GB（macOS）；脚本会在 Linux 上回退 PingFang/Noto。

## 四、四个可复用组件

`scripts/motion_kit.py` 提供四类 beat，参数见文件头。设计意图：

- **counter**：把一个关键数字（测试数、耗时、余量）从 0 滚到目标值。数字必须来自当轮验收记录，不能取整、不能合并口径。
- **grid**：把「N 次里失败 M 次」画成格子墙，失败格标 ×。适合打包次数、模块数、分区数这类可枚举数量。
- **paths**：两列对照，用连线 + 「找到 ≠ 同一处」表达路径/基准不一致。适合解释「为什么明明存在却找不到」。
- **track**：四态进度条（测试通过｜产物生成｜离线审阅｜真机部署），只点亮已发生的那几段，**未发生的永远用 dim 色并配文字说明**。

四态条是本系列最重要的防误解装置：观众看到「构建成功」很容易理解成「可以刷」，一条恒暗的「真机部署」比十句旁白都管用。

## 五、节拍

- 每个 beat 2–4 秒，一集最多两个 beat 同时存在（一般串行）。
- 进入用 ease-out（0.35–0.5 秒），离开**不做动画**，直接切下一个 beat；退出动画最容易被剪成「PPT 动画感」。
- 数字滚动 1.0–1.4 秒到位，之后保持不动；不要反复跳动。
- 与旁白对齐：按实测停顿算出的句子起点决定 beat 起点，不要用字数估。

## 六、spec 写法

```json
{
  "size": [1080, 608],
  "duration": 22,
  "fps": 30,
  "beats": [
    {"type": "counter", "start": 0, "end": 3.4, "label": "电脑端测试", "value": 1253, "caption": "全部通过"},
    {"type": "grid", "start": 3.4, "end": 10.2, "title": "21 次打包", "count": 21,
     "fail_index": 20, "fail_at": 6.6, "caption": "20 次成功，1 次退出码 2"},
    {"type": "paths", "start": 10, "end": 16.4,
     "left_label": "配置生成在", "left_title": "运行目录",
     "right_label": "打包去找在", "right_title": "配置目录",
     "verdict": "找到 ≠ 同一处", "note": "字体在运行目录，打包却按配置目录找"},
    {"type": "track", "start": 16.1, "end": 22, "lit": 1,
     "verdict": "测试通过 ≠ 打包能过", "note": "这一轮设备未连接，固件未构建"}
  ]
}
```

## 七、不该做的事

- 不把未发生的事画成已发生（例如给「真机部署」点灯）。
- 不用动效替代证据：终端/相机实拍能证明的，不要让动效抢走。
- 不在动效里写内部 id、绝对路径、用户名。
- 不为了「好看」加粒子、扫光、3D 翻转；本系列是工程纪录，不是发布会。
