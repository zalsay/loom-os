# 织界动效层

把「真实数字」变成可看的画面，让观众一眼分清测试通过、产物生成、离线审阅、真机部署这四种状态。动效只做解释，不替代证据。

## 阅读入口

- 设计原则、配色、栅格、四个组件 → [动效设计规范](references/design.md)
- 与成片合成、时序对齐、验收清单 → [接入成片管线](references/integration.md)
- 组件实现 → `scripts/motion_kit.py`（Pillow 逐帧 + ffmpeg，不依赖 Manim）

## 何时用

- 一集里出现「数字很大但只能靠旁白念」（1253 项测试、507 秒、20% 余量）。
- 出现「N 次里失败 M 次」这种数量关系，观众数不过来。
- 出现「明明存在却找不到」这种路径/基准不一致，需要两列对照。
- 相机画面全黑或终端文字太密，需要一块能看的画面补位。
- 观众容易把「构建成功」误读成「可以刷」，需要四态条压住。

不适合：纯情绪渲染、品牌片花、需要实拍证据的地方。这些不该被动效替换。

## 核心做法

1. **先有事实，再有动效**。每个数字、每个失败格都要能在当期验收记录里找到原值；找不到就不画。
2. **先定区域，再排 beat**。相机有有效信息→动效去终端区；相机黑屏→动效去设备区，终端区留实拍。
3. **按旁白句子切节拍**。用实测停顿算出每句起点，beat 的 `start`/`end` 跟句子走，不跟「第几秒」走。
4. **写 spec JSON，跑 motion_kit**。四类 beat 组合成一段 1080×608 或 1080×800 的片段，再 overlay 进成片。
5. **抽帧验收**。四个 beat 各看一到两帧，核对数字、文字不叠、未发生状态仍为暗色。

```bash
python3 scripts/motion_kit.py spec.json 动效段.mp4
```

spec 结构与示例见 [设计规范](references/design.md) 第六节。

## 四条红线

- 未发生的状态不许点灯：四态条里「真机部署」永远用 dim 色，并配一句「未发生」。
- 数字不许取整、不许换口径：1253 就是 1253，291 的 83 项与 292 的 85 项分别显示。
- 动效里不出现本机路径、用户名、内部 session id。
- 不遮终端与相机的关键证据；动效只占空白区，或被替换的那一块。

## 做完要留什么

- `spec.json`（可重跑）、`动效段.mp4`、成片，以及 `验收记录.md` 里的一行：哪些 beat 对应哪轮、哪个数字来自哪条记录。
- 抽帧证据放当期 `剪辑/审核证据-*/`，与实拍证据分开命名。
