# AI 团队协作手册（2026-10-27 定稿）

> 来源：EP09 首日数据四方分析实战复盘。2026-10-28 校准权限与证据等级：成员为 4 个 AI 角色 + 用户（最终拍板者）。文档职责与冲突审计见 [目录入口](README.md)；历史 AI 建议不自动取得执行授权。

## 一、团队成员与分工

| 成员 | 角色 | 优势 | 局限 |
| --- | --- | --- | --- |
| **buddy**（WorkBuddy） | 主持 + 授权范围内采集 + 综合建议 | 本工作流的执行入口；核对事实、汇总意见并将制作决策交用户确认 | 不以主持身份或 AI 多数票代替用户拍板；自身分析需交叉复核 |
| **agy**（Google Antigravity） | 运营策略专家 | 平台机制敏感（次级流池熔断、沙盒期）、话术模板落地能力强 | 网络最不稳定（Google 后端地区限制）；观点偏激进，需收敛执行 |
| **Codex**（gpt-6.1-sol, reasoning effort=high） | 数据审计 + 严谨性担当 | 口径核对、反事实推理最严格；敢反对多数派（如 EP10 卡秒数） | 响应最慢（4-5 分钟）；没有浏览器，只吃简报 |
| **Claude**（默认 Haiku 5.5 / high；用户明确指定 Opus 时按覆盖执行） | 数据与内容策略评审 + 口径质检、风险合规 | 独立分析数据、审查假设与风险；首轮互不参考其他成员意见 | 模型不可用时如实说明并标注回退；观点仍需核对证据，不替用户决策 |

## 二、调用方式

### run_cli_agent（Team 当前生产路径）

宿主提供 `run_cli_agent` 时，三方评审统一通过该 Tool 调用：

```text
provider: codex | agy | claude
prompt: 同一份自包含简报 + 各自评审侧重 + 只读/不委派/报告格式要求
cwd: 项目根目录
timeout_seconds: 按议题设置
read_only: true
```

- 默认模型分别为 Codex `gpt-6.1-sol--high`、agy `gemini-3.8-flash--high`、Claude `haiku-5-5--high`；回执中的 `model` 是请求值，`cliModel` 是实际传给 CLI 的模型参数。
- `read_only: true` 会启用 Codex read-only sandbox、Claude `Read/Glob/Grep` 工具限制和 agy sandbox + plan mode；不能只用 prompt 声称只读。
- 只有在 Tool 明确报告模型不可用且尚无有效评审时，才可按用户规则人工重试备选模型，并记录两次请求。超时、429/503、网络错误或已有部分输出不得盲目换模型重跑。
- `run_cli_agent` 是同步调用，不返回可恢复任务 ID。失败后先检查已有回执和缺口，再决定是否重试。

以下 CLI 命令仅用于 `run_cli_agent` 不可用且用户同意时的直连诊断，不作为 Team 首选路径。

### Claude（直连诊断）
```bash
claude -p "分析任务提示词" --model claude-opus-5-5
# Opus 5.5 无法访问时才回退，并在评审记录注明原因和实际模型：
claude -p "分析任务提示词" --model haiku
```
以实际调用结果核验模型可用性；不得将回退结果冒充 Opus 评审。

### Codex（直连诊断）
```bash
# 必须先清代理！会话注入的代理会被上游拒（HTTP 451）
unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy ALL_PROXY all_proxy
codex exec --skip-git-repo-check -m gpt-6.1-sol -c model_reasoning_effort="high" - < /tmp/video-brief-1027.md > /tmp/codex_out.txt 2>&1
```
- 曾出现 WebSocket 断连后降级 HTTPS 的个案；不把反复断连当作正常或成功证据，按实际退出码与最终输出确认完成。
- 建议后台运行（`run_in_background`），等待期间并行做其他事

### agy（直连诊断）
```bash
/tmp/agy_ask.sh "你的问题"
```
- 桥接重启后必须先走 MCP 握手（initialize → notifications/initialized）再调用
- 遇地区不可用或持续连接错误：停止该路调用并报告，使用已获准的可用评审方；不得反复循环、绕过地区限制，或把缺席方写成已参评。

## 三、标准协作流程（五步）

```
1. 采集   buddy 用 mcc 拉双平台数据 → 按格式存 copis/笔记数据/
2. 简报   buddy 写统一简报（/tmp/video-brief-NNNN.md）：
          账号背景 + 硬约束（不许推翻的既定策略）+ 数据 + 编号问题清单
3. 分跑   Claude / agy / Codex 用同一份简报独立并行，互相不见首轮输出；不可用方如实标缺席
4. 汇总   buddy 交叉验证：分别列共识、分歧、证据与建议；制作决策交用户确认
5. 定稿   用户确认后执行；讨论与确认记录落盘 EP讨论/，遗留项进下期清单
```

**简报编写的三条纪律**（来自实战教训）：
- 「已定稿约束，不要推翻」必须显式写出（如：公域标题去 EP 编号、简介合集不改），否则 AI 会重新讨论已关闭的议题
- 数据必须带口径说明（发布时间、统计截止点、累计 vs 当日），否则 AI 会自己猜口径产生假分歧
- 问题编号列出（1-5），各家按序作答，便于交叉比对

## 四、分歧裁定规则

1. **数据能终结的不辩论**：先看数据是否存在（如「EP10 该多长」的分歧，根源是总时长未记录 → 先补数据）
2. **缺数据时取交集**：激进方案（agy 压 15s）与保守方案（Codex 不卡秒数）的交集 = 以内容准绳代替数字准绳
3. **真实可证是最高否决权**：任何提升数据的建议（剪掉失败镜头、制造评论）触碰真实性红线即无效
4. **合规一票否决**：违规前科账号，任何「擦边变通」「多号刷楼」类建议只能降级执行或否决（如 agy 的协作者留言建议被裁定为：允许真人自然留言、禁止脚本化）
5. **裁定记录留痕**：每条裁定写入分析文档，注明提出方与理由，下期复盘检验对错
6. **制作决策须先 Team 讨论，再交用户拍板**（用户规则 2026-10-27，10-28 纠正旧文歧义）：标题/叙事/镜头排法/文案措辞等制作类问题，先独立并行评审 → buddy 汇总共识与分歧及理由 → 用户确认后执行。**全票或多数票均不等于用户授权**；用户已明确确认的方案内按约执行，不为同一已关闭事项重复上会。

## 五、已收敛的既定策略（简报直接引用，不许重开讨论）

- 公域标题不带 EP 编号（内部保留系列命名）
- 不擅自修改主页简介、创建/改名合集或粉丝群；发布可挂用户已确认的既有合集「织界LoomOS」。主页视频置顶由用户处理，与官方首评置顶是两项不同操作。
- 内容必须真实可证；保留失败与成人协助镜头
- 留存口径：**完播率只作平台展示值记录，留存用播放时长（人均与总时长）衡量，不做片长归一**，不拿「完播率×片长」验算或反推；两平台时长不可混算（用户 2026-11-03 裁定，细则见运营工作流手册 WF-2）
- 发布时段：**每日固定 19:30 前后**（用户规则 2026-10-27，替代此前的 A/B 时段对照方案——时段实验废止，不再作为单变量）
- 三条 10-13 图文已定性违规，不加入后续工作
- 儿童出镜：无高清脸部特写、无识别信息；标题不夸大为普遍能力提升；不伪装第三方测评

## 六、环境经验（按现状验证，不把个案固化为限制）

- 平台机制说法必须区分后台原字段、官方说明、团队假设；“熔断/沙盒/CES 权重”没有本次证据时仅可标为历史观点。
- 点击投递不等于操作生效；重观察后核对目标条目与回显。用户暂停、取消或平台警告时停止，不换通道绕过。

| 坑 | 解法 |
| --- | --- |
| Codex 报 451 / Reconnecting 循环 | 清空代理环境变量后直连（不是 clash 节点问题） |
| agy 桥接无响应 / -32602 | 桥接重启后需先 MCP 握手；urllib 收不到 SSE 流，用 curl 后台流 |
| 曾出现连接跨命令失效 | 按实际连接状态重观察；必要时在同一命令链 observe→click→observe，不推断所有连接必然跨命令失效 |
| mcc 输出重名报错 | 每次用唯一文件名 |
| 视频号登录态丢失 | 「微信快捷登录」可自动授权；登录按钮点击要看图定位，不能只信 OCR |
| 文档替换范围不当可能丢失标题 | 使用唯一匹配，修改后检查差异与结构；不把编辑失误写成工具必然缺陷 |
