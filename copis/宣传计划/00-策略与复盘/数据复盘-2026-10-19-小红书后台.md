## 一、后台数据拉取流程（copis-chrome v0.1.2，本次沉淀）

### 标准链路
1. 定位组件：读 `~/.copis/modules/active.json` → `versions/chrome-desktop-cli/<版本>/copis-chrome-0.1.2-darwin-arm64/copis-chrome`（与 helper 同目录，三个文件必须相邻）。
2. `--version` → `permissions` → `windows` → `connect --window <id>`，保存 `connectionId` 跨命令复用，不要每轮重连。
3. `observe` 得 `frameId` + `imagePath`（JPEG 最长边 1600），**用读图工具看图后再定坐标**；x/y 是图内整数像素坐标，CLI 自动映射屏幕，不乘 Retina 倍率。
4. 键盘导航优先（`Cmd+L` + 输入网址 + `Enter`），已知网址直达最稳；`sent:true` 只代表事件已投递，页面结果必须重新 `observe` 确认。
5. 页面内导航：`click --frame <frameId> --x --y`；同一 frameId 可重复用，窗口几何变化后重新 observe。
6. 完成后 `disconnect`；daemon 需常驻时用后台任务方式跑 `daemon run`（`daemon start` 的分离进程会被宿主环境回收）。

### 本次踩坑实录（下次直接避开）
| 坑 | 现象 | 处理 |
| --- | --- | --- |
| daemon 被回收 | `daemon start` 后随即 `running:false` | 改为后台任务常驻 `daemon run` |
| 权限授予主体 | 屏幕录制列表里没有 helper | 授权记在宿主应用头上，找**同名条目**开屏幕录制 + 辅助功能，授权后重启 daemon |
| POINTER_OBSCURED 全屏命中 | 任何坐标点击都报"被覆盖" | MonitorControl 的全屏遮罩（layer 极高）+ Dock 异常全屏窗口叠加导致；本机 CLI 点击基本不可用 |
| CLI 点击不可用的替代 | — | 用 Python Quartz `CGEventPost` 投递真实鼠标事件（隔离 venv 装 `pyobjc-framework-Quartz`），先 `activate Chrome` 再按「图内坐标 × (窗口宽/图宽)」换算全局坐标；键盘（press/type）始终走 CLI |
| 滚轮事件无效 | CGEvent 滚轮不落页 | 先点击表格空白处获焦点，再用 CLI `press PageDown`；或点分页/标签按钮代替滚动 |
| osascript 控制 Chrome 写操作挂起 | `set bounds`、`get bounds` 卡死被 SIGTERM | 放弃 AppleScript 写操作，只用 `activate` |
| 观察点被遮挡的排查 | — | `CGWindowListCopyWindowInfo` 列出目标点全部窗口按层排查（Swift 片段见 /tmp/winat.swift 模式） |

### 坐标换算公式（Quartz 兜底点击用）
`global = window.xy + image_xy × (window.w / image.w, window.h / image.h)`，其中 window 来自 CLI `windows`，image 尺寸来自 `observe`（本例 1600×927，窗口 1685×976，比例 ≈1.053）。
