## 一、环境与前置

- CLI 路径：从 `~/.copis/modules/active.json` 的 `chrome-desktop-cli.versionDir` 解析，`entrypoint` 即二进制（如 `copis-chrome-0.1.11-darwin-arm64/copis-chrome`）
- daemon：`daemon run` 挂后台任务常驻（`daemon start` 分离进程会被回收）；报 `sandbox-center cmd decisionRecord` 错重试即可
- 连接：`windows` 找 windowId → `connect --window <id>`，记下 connectionId；**0.1.11 起 press/type/click/scroll 全部强制要求 `--frame`**（observe 返回 frameId）
- 窗口判断：连接前用 `windows` 看 title（「视频号助手」）；Chrome 重启后 windowId 会变
- **窗口被移动/缩放后必须 disconnect → connect 重连**，否则 daemon 缓存旧几何导致坐标全错
- 登录态：channels.weixin.qq.com 保持登录（失效时手机扫码）

## 二、坐标获取方法论（重要）

**首选：observe 返回 JSON 的 `ocr.items`**（bbox/center，frame 像素）——这是可靠的坐标源，与实际命中完全吻合：

```bash
$CLI observe --connection $CONN --out /tmp/obs.jpg > /tmp/obs.json 2>&1
python3 -c "import json; [print(f\"({int(i['center']['x'])},{int(i['center']['y'])}) {i['text']}\") for i in json.load(open('/tmp/obs.json'))['ocr']['items']]"
```

**不要从 Read 显示图肉眼量坐标**——显示图被缩放（如 ÷1.212），量出的 y 会系统性偏小，点击全部落空。  
observe JSON 还有 `coordinateSpace`/`imageTransform` 字段可用于换算校验。  
点击返回的 `screenPoint` = 窗口原点 + 图片坐标换算，可用于全屏截图落点验证。

## 三-A、微信快捷登录（2026-10-26 EP09 实测，Chrome 重启后登录态丢失时的替代路线）

登录态失效（URL 跳 `login.html`）时不必手机扫码——**本机微信桌面客户端在线即可快捷登录**：

1. 刷新登录页（Cmd+R）→ 登录面板出现本机微信身份（头像 +「微信快捷登录」绿色按钮 +「使用其他头像、昵称或账号」）；若先出现二维码，刷新一次即切回快捷登录
2. 点「微信快捷登录」→ **微信客户端弹出独立确认小窗**（约 360×260，"视频号创作平台申请使用你的昵称、头像"）
3. ⚠️ 该小窗是独立原生窗口（mcc `windows` 里新增的无标题微信窗口），**不能复用 Chrome 连接**：disconnect Chrome → connect 小窗 → observe → 点「允许」→ disconnect → reconnect Chrome，页面即登录成功并跳转平台内页
4. 注意 daemon 同时只允许一个连接，切换窗口必须先 disconnect

## 四、输入与编辑要点

- **多行文本**：逐段 `type` + `press Enter`，`\n` 不可靠；回车键名用 `Enter`（`Return` 不在允许的 21 键内）
- **中途被 FOCUS_LOST 打断后，光标位置不可靠**：不要直接续输（可能插进中间）；点入文本框 → `Cmd+A` → `Backspace` 清空重打最稳（EP07 实测：描述 4 段+话题整体重打一次成功）
- **`ACTIVATION_FAILED`（系统未允许激活目标应用）**：先 `osascript -e 'tell application "Google Chrome" to activate'` 前置激活，再重试输入（EP07 实测有效）
- **清空重来**：点入文本框 → `press Cmd+A` → `press Backspace` 或 `Delete`（均可用）；不要试图点行首补字，极易重复
- **打错位置**：光标停在插入点，先 `Cmd+A` 全选清空再重打，比逐字删除稳
- **Cmd+Up / Home 不在按键白名单**；光标回开头只能靠点击行首位置（不稳，建议清空重打）
- **粘贴不可靠**：contenteditable 输入框 CLI `press Cmd+V` 和 CGEventPost Cmd+V 均可能无效，用 `type` 逐段输入
- **下拉框**：点开后再点选项即选定；`Escape` 可关；点空白处关闭也可
- 布局会随内容变化位移（描述填完页面变高），**点击前必须重新 observe 取新 frame 和坐标**，不要复用旧坐标


## 三-C、短标题字符规则（EP09 实测）

短标题含**中文逗号会触发红色校验错误并禁用「发表」按钮**。规则原文：符号仅支持书名号、引号、冒号、加号、问号、百分号、摄氏度，**逗号可用空格代替**。定稿标题含逗号时，视频号短标题用空格分隔（如「只点了一次 这份备份收全了」）；小红书标题不受此限。另：短标题加「织界 EPXX：」前缀易超 ≤16 字限制，直接用定稿标题原文即可。

## 五、2026-10-27 EP10 发布新增教训

1. **发布页入口**：直接 URL `/platform/post/video` 主区白屏（SPA 该路由不渲染）；正确做法是**从首页「发表视频」按钮进**（SPA 内部路由）。正确 URL 为 `/platform/post/create`，但直接输 URL 打开同样白屏——必须按钮进。
2. **描述框受控组件覆盖**：发布页描述框（contenteditable 受控组件）会周期性用内部 state 回写覆盖 DOM，**长文案（≥4 段）多段 type 必丢段**（快速/慢速/预热全试过均不稳，且每次丢的段落随机）。EP10 定版方案：**描述压到两句话以内**（用户拍板），一次 type 成功率高；长文案走「发布物料 TXT + 人工粘贴」。
3. **mcc 键名大小写敏感**：`Enter`/`Backspace`/`Home`/`Cmd+A` 大写可用；`return`/`enter`/`cmd+a` 小写全被拒。`Cmd+V` 不在白名单。`type` 不接受换行符（控制字符），逐段 type + `press Enter`。
4. **实时发表后短时间不可编辑**：点「发表」→ 跳回列表即发布成功，但随即点「修改描述和封面」不跳转（疑似审核中锁定编辑）。需等审核通过后再进编辑页补封面/位置/合集/标注（§三-B 流程适用）。
5. **列表 hover 按钮**：先 click 条目右侧空白（约 (1100, 条目y)）触发 hover，按钮区浮现于 x≈1090-1530（置顶/分享/评论管理/修改描述和封面/可见权限/删除），再点目标按钮；注意列表页 ViewImage 缩放，坐标以 observe OCR 原像素为准。
6. **短标题中文逗号会禁用发表**（§三-C 已记），本次再验证：改空格后正常。
7. **⚠️ hover 按钮行归属必须核对条目行范围**（19:47 重发轮教训，险些删错）：列表顶部可能混有**置顶条目**（EP02「取消置顶」），hover 位置偏一条，按钮行就属于另一条视频。点「删除」等危险按钮前，必须截图确认按钮行 y 坐标落在目标条目的行范围内（缩略图+发布时间+描述三要素核对），只看「按钮出现了」不够。
8. **列表「删除」按钮合成点击无效**（19:35 旧条实测 4+ 次）：确认弹窗从未出现，双击也不行——列表 hover 操作按钮区对 mcc 合成点击不稳定，最终由用户手动删除。删除类操作建议直接请用户手动做，CLI 只做非破坏性步骤。
9. **评论置顶菜单项合成点击无效**（20:10 首评轮实测）：评论管理页 → hover 评论 → ··· 菜单能正常弹出（坐标 (1456,662)），但「置顶」菜单项 (1386,737) 多次单点/双击均无响应（菜单项文字始终不变、无置顶角标）——浮层菜单项是合成点击盲区，由用户手动点击完成。菜单项坐标定位法：裁剪小区域放大截图读坐标，比 OCR 稳。
10. **截图量坐标必须乘缩放系数**：全屏 3440×1440 1x，ViewImage 显示图会被缩到 1080 宽——从显示图量出的坐标要 ×1.481 才是实际像素。封面 + 虚线框第一次点偏（漏乘）、评论 ··· 第一次点偏 30px 均此因。保险做法：裁剪原尺寸小区域放大后再量，或直接信 observe OCR。
11. **位置搜索框受控组件会拼接重复文本**：type「融侨江南水都·名筑」后输入框显示「融侨江融侨江南水都·名筑南水都·名筑」（回写拼接），搜索结果仍正确；若结果异常，清空重输一次。
12. **USER_PAUSED 后已发出的点击会落空**：控制条暂停瞬间发出的 click 静默丢失（POI 选择点击无效），恢复后须整步重做（重开下拉→重搜→重选），不要假设上一步已生效。
13. **首评文案必须说人话**：技术口径（SHA-256/HTTP 请求/文件名）直出会被用户打回；白话版结构 = 「报实底（结果）→ 数说了什么 → 视频里的板子是什么 → 还没做什么 → 下一集预告 + 关注钩子」。定稿见 EP10 发布物料 TXT「首评-白话版」。
