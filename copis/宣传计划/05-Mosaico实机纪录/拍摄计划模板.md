## 3. 现场设备与机位

- 主机位：竖屏 9:16，固定、稳定、锁定曝光和对焦。
- 辅机位：近景 / 屏幕 / 手部；没有辅机位时主机位优先保证完整动作。
- 屏幕录制：代码、终端、编译、日志或设备画面单独录制，避免拍屏闪烁。
- 声音：现场口述或后期旁白二选一；即使不收现场声，也录 10 秒环境底噪。
- 同步：只有多台设备同时录制同一事件、需要同步时才在开头拍手；单机拍摄不强制。
- 隐私：序列号、账号、Wi-Fi、密钥、儿童姓名和学校先避开，无法避开则后期遮挡。

默认先提供单人单手机方案。固定机位连续保留不可重复的关键过程；拆封、首次上电和首次出现的报错不能为了镜头效果重演。补拍只能补可重复的外观或状态，记录为“补拍”，不能伪装成首次结果。

对于代码、编译和日志，用独立屏幕录制；手机拍手部和设备即可。若两者不能同时录制，优先保留真实结果和日志，而不是丢掉测试只顾拍特写。暂停录屏处理密钥、密码和账号信息，恢复后记录实际断点。

| 镜头 ID | 时长 | 必拍动作 | 机位/景别 | 现场口述 | 成功标准 | 实际结果 |
| --- | ---: | --- | --- | --- | --- | --- |
| S01 | 5–10s | 交代环境和设备 | 固定全景 | 今天要验证什么 | 观众知道问题 |  |
| S02 | 5–10s | 展示关键物件 | 俯拍/近景 | 这是什么、为什么需要 | 物件清楚 |  |
| S03 | 10–30s | 执行核心动作 | 主机位 | 现在做哪一步 | 动作完整 |  |
| S04 | 10–30s | 记录中间状态 | 屏幕/手部 | 看到什么 | 细节可读 |  |
| S05 | 5–20s | 展示结果或错误 | 主机位/屏幕 | 成功或哪里没过 | 不剪掉真实结果 |  |

每个关键动作至少拍一条完整长镜头，再补 2–3 条近景；不要只拍零散特写导致动作无法复原。

不要要求每个镜头 ID 单独成为文件：一条长镜头可以覆盖多个 ID，用户交原文件名和简短时间标记即可。拍摄建议时长是留素材，不是要求现场表演或等待固定时间。

## 5. 现场口述提示

不用背稿，只需回答：

1. 我现在想解决什么问题？
2. 我准备先做哪一步？
3. 我根据什么判断成功或失败？
4. 结果和预期一样吗？
5. 下一步准备改什么？

## 6. 拍完交接

- 素材目录：`EP__-主题/原始素材/`
- 文件命名：`S01-环境.mp4`、`S03-核心动作-A.mp4`、`SCREEN-编译日志.mp4`。
- 同一天素材不要覆盖；补拍使用 `-take02`、`-take03`。
- 附一份 `拍摄备注.md`，写明每条素材发生了什么、是否为真实结果、哪些片段不能公开。
- 同时提供代码 commit、固件版本、Runtime 版本和错误日志；没有的写“未记录”。

原始素材只要能定位即可，批量重命名、拆分镜头、去掉无效段落由 Copis Agent 在工作副本中完成，不修改唯一原件。后期先做素材验收，集中列出必须补拍项；有足够素材才进入剪辑、配音和导出。

## 交付状态与失败分支

- 未开拍：仅有拍摄计划，不称视频已生成。
- 素材已到：先确认可读性、声音、授权和事实来源；不预设拍到了成功。
- 测试未通过：拍下错误、保留日志，用“这一步还没过”收尾。
- 拍漏首次事件：明确缺失，只补外观或讲述，不重演第一次。
- 可剪辑：按真实素材写成片稿；时间安排、字幕和配音依实际素材调整。
- 已导出：再记录视频位置、版本、检查项和未完成事项；未发布就标未发布。
