## 二、与分镜稿的冲突（必须调整后再渲染）

1. **0–3s “首帧即见 completed / 由 pending 转 completed”**
   - 录像 0s 处是「等待」而非「completed」；completed 出现在 **141.97s**（按 session.json 时间戳推算；抽帧粗测约 141.6s）。
   - 若要冷开场使用完成回执，只能是**闪前剪辑**（从 141.6s 取镜回置到片头），必须明确它是闪前，不得让观众以为这是开机第一秒的实时顺序。
   - 「pending→completed」的重绘只有约 0.2s，可用慢放/定格强调，但它是**一帧级重绘**，不是持续动画。

2. **14.5–18.5s “双路切真机硬件（主板、通电指示灯）”**
   - 相机素材里**没有主板特写、没有指示灯特写**，也没有可见的点击动作；只有固定的 Works 列表，设备偏小。
   - 该镜头按现稿无法兑现。可选替代：
     a) 用相机 Works 列表的紧裁 + 缓慢推近（取景运动），旁白只讲“设备回到了 Works”，不声称任何按键/指示灯；
     b) 删掉该段，把 14.5–18.5s 留给终端 JSON 的局部推近与金句字幕。

3. **“7 项 capabilities 完整行”可读性**
   - JSON 以 5 行长文本折行显示，原片字号小；裁切放大 1.5–2× 后可用，但会有明显软化。
   - 建议只放大 `capabilities` 一段与 `"state":"partial"` 一段，做两次短推近，而不是要求“完整行清晰”。

4. **141s 静止等待**
   - 若如实展示“等了一分多钟”，必须用时间压缩（setpts）或直接跳切，并在字幕/口播说明“等了一分多钟”；不能把 141s 的静止硬剪进 24s 而不交代。
