# 数据读取工作流

> **任务目标**：在本机 Chrome 中读取小红书创作中心和视频号助手的数据，刷新页面、提取指标并保存为可校验的 Markdown 文档。  
> **适用环境**：macOS、本机 Google Chrome、Copis 本机 Chrome 控制能力。  
> **覆盖平台**：小红书创作服务平台、微信视频号助手。  
> **前置依赖**：两个平台均已在同一个 Chrome 用户配置中登录；已获得 Chrome 窗口观察授权；项目默认产物目录为 `/Volumes/RC500/dev/loom-os/copis/`。

## 一、通用 Chrome 连接流程

### 步骤 1：连接并观察本机 Chrome

- **操作目的**：建立对目标 Chrome 窗口的观察能力，确认当前页面和窗口状态。
- **执行方式**：
  1. 调用 `ChromeDesktopStart`，等待用户选择并授权目标 Chrome 窗口。
  2. 调用 `ChromeDesktopObserve`，取得当前 `controlId`、`frameId` 和画面。
- **验证要点**：
  - 返回结果中包含有效的 `controlId` 和 `frameId`。
  - 截图中确实显示 Google Chrome。
  - 后续操作复用同一个有效 `controlId`，不要重复授权。
- **前台行为**：
  - `ChromeDesktopObserve` 只读取画面，不会主动把 Chrome 切到前台。
  - `ChromeDesktopClick`、`ChromeDesktopScroll`、`ChromeDesktopType` 和 `ChromeDesktopPress` 会激活目标窗口。
  - 只读取已打开页面时，不要额外执行 AppleScript `activate`；确实需要点击或滚动时，再允许 Chrome 获得前台焦点。

## 四、关键技术决策与实施要点

1. **使用精确域名匹配平台标签页**
   - **决策内容**：小红书只匹配 `https://creator.xiaohongshu.com`，视频号只匹配 `https://channels.weixin.qq.com`。
   - **原因与权衡**：Chrome 中可能同时存在普通小红书页面和多个微信后台标签。精确域名能避免刷新错页面。

2. **观察与输入采用不同的前台策略**
   - **决策内容**：纯读取直接使用 `ChromeDesktopObserve`；点击、滚动、键盘输入才接受窗口前台激活。
   - **原因与权衡**：可以减少对用户当前工作的干扰，同时保留需要精确交互时的能力。

3. **使用 AppleScript 作为焦点输入回退方案**
   - **决策内容**：Chrome 桌面输入接口返回焦点错误时，通过 AppleScript 定位标签页和刷新。
   - **原因与权衡**：观察接口仍正常，而 AppleScript 能在同一个本机 Chrome 会话内完成页面控制；纯刷新命令不调用 `activate`。

4. **以页面实际可见数据为准**
   - **决策内容**：不补全被截断的标题，不推测未展示的发布时间或指标，不把图表中的“全部”重复计入分项。
   - **原因与权衡**：工作流需要可审计；任何补全或重复计算都可能改变数据口径。

5. **汇总与交叉校验使用 Python**
   - **决策内容**：用 Python 对原始指标列求和，并单独验证视频号来源分项。
   - **原因与权衡**：降低多列汇总和总量/分项校验中的抄写、计算错误。

## 五、踩坑记录与避坑指南

| 异常现象 / 报错信息 | 根本原因（Root Cause） | 正确解决方案与预防措施 |
| --- | --- | --- |
| `chromeDesktopControl` 工具不存在 | 实际工具使用 `ChromeDesktop*` 命名，而不是单一控制入口 | 使用 `ChromeDesktopStart`、`ChromeDesktopObserve`、`ChromeDesktopClick` 等完整工具组 |
| 输入操作返回 `CHROME_FOCUS_LOST` | macOS 前台焦点或输入焦点未稳定落到 Chrome，点击、快捷键均可能失败 | 重新观察后重试；若仍失败，改用 AppleScript 精确选择 URL 所在标签并刷新 |
| 控制会话返回 `CHROME_CAPABILITY_STALE` | 控制会话过期或没有活跃的 Chrome 控制任务 | 重新调用 `ChromeDesktopStart`，再调用 `ChromeDesktopObserve`；不要假定旧 `controlId` 永久有效 |
| 第一次刷新到了普通小红书首页 | 匹配范围使用了 `xiaohongshu.com`，同时命中 `www.xiaohongshu.com` 和创作中心 | 只匹配 `https://creator.xiaohongshu.com` 前缀 |
| 多窗口场景下只看到一部分标签页 | Chrome 可能同时存在多个窗口 | 遍历 `windows`，再遍历每个窗口的 `tabs`，不要只检查 `front window` |
| 表格看似只有几行而总计更多 | 页面可能分页，当前视口也未必展示全部行 | 同时检查“共 N 条”和分页区域；若总数大于当前页条数，必须继续翻页 |
| 标题末尾出现省略号 | 页面标题本身被截断 | 保留省略号，并在文档说明中注明，不自行猜测完整标题 |
| 视频号表头只有图标 | 页面用图标表达喜欢、推荐等指标 | 按页面“数据类型”的排列顺序映射，并在文档中保留识别说明 |
| 视频号来源合计翻倍 | 把来源“全部”和各个来源分项一起相加 | 只对各分项求和，并验证分项之和等于“全部” |
| 手工汇总存在误差风险 | 多行、多列数字逐项相加容易出错 | 保存后运行 Python 求和脚本，与文档汇总表比对 |

## 七、后续复用与扩展建议

- **动态参数**：复用时应替换数据日期范围、导出日期、目标 URL 和输出文件名。
- **稳定匹配**：始终按域名和页面路径定位标签页；平台改版后先重新确认统计页面路径和字段顺序。
- **月份归档**：使用读取日期所在月份归档；跨月统计在文档头部明确记录统计起止日期。
- **批量历史数据**：若需要多日期范围或翻页，可在每一步截图后记录页码和筛选条件，最后合并并按唯一日期或笔记标识去重。
- **自动化方向**：可将标签定位、后台刷新、字段提取、文件命名和汇总校验封装为固定脚本；账号登录、页面结构变化和数据准确性仍应在执行后人工核验。
