# 视频号电脑版自动化发布——技术要点

> 2026-10-14 首次走通：上传 MP4 → 填描述/短标题 → 发表成功（账号「Meetlife觅见未来」）。
> 适用场景：微信视频号助手 channels.weixin.qq.com 的电脑版发表流程；部分经验通用于其他 wujie 微前端站点。

## 一、总体流程（已验证可复用）

1. `agent-browser open "https://channels.weixin.qq.com/platform"` → 微信扫码（二维码从截图裁剪，白底检测定位边界最准）
2. 首页 snapshot 找 `button "发表视频"` 的 ref → `click @ref` 进入 `/platform/post/create`
3. **上传视频**：CLI upload 无效，走 CDP 注入（见第二节）
4. **填表**：上传成功后页面刷新为表单 → 描述/短标题用 `keyboard type` + `press Enter` 逐段输入（见第三节）
5. `snapshot` 找 `button "发表"` ref → `click @ref` → 跳转 `/platform/post/list` 且顶部出现「已发表」toast = 成功

## 二、上传视频：wujie shadow DOM 绕行（核心难点）

### 为什么 CLI 的 upload 失败

- 视频号助手是 **wujie 微前端**，整块应用渲染在 `WUJIE-APP` 的**闭式 shadow DOM** 里
- 症状：截图能看到上传卡片、snapshot 能给 ref，但 `eval` 的 `document.querySelectorAll('input')` 返回空、`upload @ref` 报 `Node is not a file input element`
- playwright（agent-browser 底层）会**静默吞掉 filechooser 事件**：直接点击上传区不会弹原生文件框、也没有任何反应——点击像消失了一样

### 解法：原生 CDP 注入文件（无需任何 npm 依赖，Node 22 自带 WebSocket）

```bash
# 1. 拿 CDP 地址
agent-browser get cdp-url
# → ws://127.0.0.1:63821/devtools/browser/xxxx

# 2. 穿透 DOM 找 file input（脚本：发布技术/find-input.mjs）
node find-input.mjs "ws://.../devtools/browser/xxxx"
# 输出 accept="video/mp4,video/x-m4v,video/*" 的 input nodeId

# 3. 注入文件（脚本：发布技术/set-files.mjs，会自动重新查找 nodeId）
node set-files.mjs "ws://..." "/path/to/video.mp4"
# → FILES SET OK
```

关键 CDP 调用链：
- `Target.getTargets` 找 `type==='page'` 且 URL 匹配的 target
- `Target.attachToTarget {flatten:true}` 拿 sessionId
- `DOM.getDocument {depth:-1, pierce:true}` —— **pierce:true 是穿透 shadow DOM 的关键**
- 递归遍历 `children` + `shadowRoots` + `contentDocument`，按 `type==='file' && accept 含 video` 定位
- `DOM.setFileInputFiles {files:[路径], nodeId}` —— 注入后应用的 onchange 正常触发，上传启动

注意：**nodeId 每次连接会变**，set-files.mjs 已做成每次自动重新查找。

## 三、填表：shadow DOM 里的键盘输入

- **粘贴（Cmd+V）和 Cmd+A 全选在 wujie shadow DOM 里无效**（组合键被吞），不要依赖
- 可靠做法：点击输入框获得焦点（真实坐标点击）→ `keyboard type "文本"`（真实键击，中文 OK）→ 段落间 `press Enter`
- 描述里的 `#话题` 输入后自动转蓝色话题链，无需走「#话题」按钮
- 内容可编辑框没有 ref 时，用截图坐标点击即可获得焦点
- **多行文本**：分段 type + press Enter，不要指望 `\n` 或剪贴板

## 四、坐标换算（反复踩坑）

- agent-browser 截图会被 Read 工具**缩放显示**，显示坐标 ≠ 视口坐标，必须换算：
  - 视口 1280 宽、截图显示 1080 → ×1.185
  - 视口 1440 宽、截图显示 1080 → ×1.333
- 换算错了不会报错，只会把字打进**别的输入框**（本次曾把短标题文字打进了描述框中部）
- 打错位置先别慌：光标停在插入点后面，`press Backspace`×N 即可修复
- 元素真实坐标优先用 `snapshot` ref + `get box @ref`（返回 x/y/width/height，是视口坐标，无需换算）

## 五、其他坑位速查

| 坑 | 表现 | 处理 |
| --- | --- | --- |
| SPA 路由拦截 | 直接 open `/platform/post/create` 被重定向回 `/platform` | 从首页点「发表视频」按钮进入 |
| 主页面滚不动 | `mouse wheel` 无反应（滚的是内层容器） | `set viewport` 加大高度（如 1440×1600）让表单完整可见，避免滚动 |
| 找不到按钮 | eval 找不到文本（shadow DOM），snapshot 能看到 | 一律用 snapshot ref 点击，不用 eval 查 DOM |
| 登录二维码裁歪 | 扫不出来 | 用白底检测（灰度 >235）定位边界再裁剪，别按显示坐标估 |

## 六、可复用脚本

均在 `宣传计划/发布技术/`：

- `find-input.mjs` —— 穿透 DOM 列出所有 file input（nodeId、accept、路径）
- `set-files.mjs` —— 自动查找 video file input 并注入文件（**发布上传用这个**）
- `fc-upload.mjs` —— filechooser 事件拦截方案（本站被 playwright 抢先拦截，未生效；留作其他站点参考）

## 七、合规边界（原则）

- 自动化仅用于**发布流程本身**与**只读数据拉取**；不做伪装人类节奏、隐藏自动化特征等规避平台风控的操作
- 小红书曾预警「脚本(AI)读取数据」——发布类操作如平台敏感，优先手动；视频号助手电脑版对自动化目前宽容，发布流程可继续走本方案

## 八、发布后核对

- 描述开头首行 = 钩子句（信息流只露前两行）
